# Аудит QUIP — 10 сентября 2026

## Исправленные проблемы

| Проблема | Причина и изменение |
| --- | --- |
| OpenRouter сразу падает при временном DNS-сбое | Три ограниченные попытки подключения. Диагностика DNS/VPN/proxy, без повторов уже начатой генерации |
| Админка недоступна при сбое OpenRouter | Запрос метаданных ключа больше не прерывает страницу настроек |
| Каталог моделей пропадает после сетевого сбоя | Ошибка не кешируется как пустой список на пять минут; сохраняется последняя известная копия |
| Ollama требует OpenRouter API key | Выбор провайдера восстановлен для отправки и регенерации; исправлен формат мультимодальной истории Ollama |
| Изменяется переданная история сообщений | Anthropic cache markers теперь добавляются в глубокую копию мультимодального содержимого |
| Ошибка потока не видна после начала ответа | Ошибка хранится отдельно, отображается вместе с частичным ответом; поддержаны оба формата события error |
| SSE теряет события или портит кириллицу | Парсер выделен в отдельный модуль, обрабатывает UTF-8, CRLF, многострочные данные и последний неполный кадр |
| Повтор после HTTP-ошибки ломает ключи списка | Временные сообщения получают уникальные локальные ID; новая отправка не создаёт дубли |
| Выделение исчезает при генерации | Обновление выбранного DOM-блока откладывается; накопленный текст появляется после снятия выделения |
| Автопрокрутка мешает читать/выделять | Не выполняется при выделении и перетаскивании; следит за тем, остался ли читатель внизу |
| Composer перекрывает ответ | Реальная высота поля ввода участвует в layout; фиксированный нижний отступ убран |
| Не видно текст в светлой теме | Общие семантические токены вместо фиксированных тёмных цветов; повышен контраст вторичного текста |
| Нечитаемая/неполная разметка ответа | Подсветка кода для обеих тем, списки, прокрутка таблиц, видимые кнопки копирования |
| Markdown повреждает `items[1]` и URL | Преобразование ссылок-источников применяется только к тексту вне кода и атрибутов |
| HTML из языковой метки code fence | Метка экранируется; ссылки рендерят вложенные inline tokens; inline onclick убран |
| Исчезает заключение после списка источников | Текст после списка сохраняется |
| Пагинация перескакивает страницу после ошибки | Offset меняется только после успешной загрузки; конкурентная подгрузка исключена |
| Поздний ответ открывает старый чат/список | Версии запросов защищают от устаревших результатов |
| Telegram polling скрывает сообщения каждые 4 сек | Фоновая загрузка без spinner и замены одинакового состояния |
| Кнопка входа/регистрации зависает без сети | Ошибка показывается, loading сбрасывается в finally |
| Время сообщений сдвинуто на 3 часа | SQLite timestamps без timezone интерпретируются как UTC |
| Dev launcher не запускает npm на Linux | Убран shell=True со списком аргументов, используется backend venv, есть корректное завершение процессов |
| Локальный backend не читает корневой .env | Загрузка до импортов БД/провайдеров; зависимость объявлена явно |
| Dev Compose не передаёт OpenRouter key | Добавлены OPENROUTER_API_KEY и JWT_SECRET |
| Readiness падает на чистой установке | Каталог data создаётся при старте |
| Все тесты требуют живой Docker daemon | Docker client создаётся при первом использовании, а не при импорте executor |
| Dev регистрирует отсутствующий sw.js | Убрана ручная регистрация; production PWA регистрируется штатным плагином |

## Структура

Сетевой код, типы провайдеров, SSE framing, обработка событий, поведение выделения и стили тем разделены на самостоятельные модули. Публичные импорты типов провайдеров сохранены. Добавлены README, карта архитектуры, сетевой doctor и этот отчёт; снято общее исключение docs из Git.

## Проверки

- Backend: **148 тестов прошли**, включая Ollama без OpenRouter key, повтор подключения, отказ после частичного ответа, авторизацию, изоляцию файлов, миграции и безопасность executor.
- Frontend: **28 тестов прошли**, включая framing SSE, сохранение выделения, Markdown, пагинацию, гонки загрузки и повтор после ошибки.
- `svelte-check`: 0 ошибок, 0 предупреждений.
- Локальная production-сборка frontend: успешно; остаются предупреждения о размерах больших vendor chunks и Node 26 deprecation, а также PWA glob для отсутствующих prerendered страниц (приложение работает как SPA). CI использует Node 22.
- Ручная проверка в браузере: вход; длинный чат с кодом, таблицами и списками; две темы; выделение; копирование кода с проверкой содержимого clipboard; отправка; повторная генерация; остановка; мобильная ширина 390 px без горизонтального overflow.
- Браузерные сценарии запускались с отдельной SQLite-базой в `/tmp` и локальной имитацией Ollama. Пользовательские данные не использовались.
- Публичный endpoint OpenRouter отвечает HTTP 200 с хоста; платный запрос генерации с реальным ключом не выполнялся.

После первого пуша workflow GitHub Actions остановился на `pip-audit`: lockfile содержал уязвимые `aiohttp 3.14.1` и `cryptography 49.0.0`. В отдельном исправлении обновлены только эти пакеты до `3.14.3` и `50.0.1` соответственно. Проверка уязвимостей в CI сохранена.

## Что остаётся за границами проверки

1. **Постоянно сломанный DNS нельзя починить retry-кодом.** В ограниченной среде DNS недоступен; с хоста обнаружен VPN fake-IP адрес и рабочий HTTPS. Docker socket недоступен текущему пользователю, поэтому сеть production-контейнера не проверена. Инструкция описывает проверку из того же контейнера.
2. **Реальные интеграции** Telegram, генерации изображений/музыки, OCR и Docker sandbox не проверялись end-to-end с внешними сервисами. Их существующие автоматические тесты прошли.
3. **Зависимости:** `npm audit --omit=dev` показал 4 moderate и 0 high/critical. В полном дереве dev-зависимостей тоже есть advisories. Автоматический `audit fix --force` не применялся, поскольку он предлагает несовместимую смену версии svelte-i18n. Обновление зависимостей стоит вести отдельным изменением с проверкой сборки.
4. **Размер клиента:** Mermaid/highlight.js остаются крупными пакетами. Для следующего этапа можно ограничить набор языков и видов диаграмм.
5. **CompletionService** остаётся большим. Текущий рефакторинг выделяет места выявленных дефектов; дальнейшее разделение persistence/orchestration нужно делать с сохранением транзакционных гарантий.

6. **Завершение после отмены:** при остановке тестового backend после ручной отмены ответа SQLAlchemy вывел предупреждение о невозвращённом соединении. UI-отмена работает, но очистку DB-сессий при отмене/остановке сервера следует отдельно воспроизвести и проверить; устранение этой проблемы здесь не подтверждено.

Это проверенный набор исправлений и карта дальнейшей работы, а не утверждение об отсутствии всех возможных дефектов.
